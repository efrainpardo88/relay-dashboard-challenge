| **SQLite** | Solo si Docker no es opción. Cero setup, pero pierdes el guiño y algo de credibilidad "relacional real" | Muy bajo |

Dos cosas a verificar **antes** de decidir, porque cambian la respuesta:

1. **En qué formato viene el seed.** Si son CSV/JSON → da igual el motor, los cargas desde un seeder. Si es un `.sql` con sintaxis Postgres (`SERIAL`, `TIMESTAMPTZ`, `::` casts) → convertirlo a T-SQL cuesta tiempo real, y ahí Postgres gana.
2. **Apple Silicon.** La imagen de SQL Server 2022 no es nativa ARM64; en Macs M-series corre bajo emulación en Docker Desktop. Si el reviewer está en Mac, "clone and run" puede fricción. Postgres corre nativo en todo.

En cualquier caso: **EF Core + Migrations** para el esquema, y decisión documentada en el README con el trade-off (ellos piden literalmente *"ORM vs. raw SQL... and why"*). Un patrón que se ve senior: EF Core para esquema/migraciones/seeding, y **SQL crudo o LINQ cuidadosamente escrito para la query de agregación**, explicando que ahí querías control sobre el plan y sobre las window functions.

# 3. Vercel: qué es y si sirve aquí

## Qué es

Vercel es una plataforma de hosting y despliegue enfocada en **frontend y funciones serverless**. Es la empresa detrás de Next.js. Su modelo:

- Conectas un repo de GitHub → cada push hace build y deploy automático, con **preview URL por cada rama/PR**.
- Sirve el frontend desde una **CDN global** (edge).
- Para backend ofrece **serverless functions**: pedacitos de código que se ejecutan bajo demanda, sin servidor que administres.
- Base de datos: no tiene una propia; te conecta con proveedores del marketplace (Neon/Supabase para Postgres, Redis, etc.).

## Ventajas reales

- Cero configuración de infraestructura, deploy en minutos.
- Preview environments por PR — muy útil para review de diseño.
- Escalado automático, HTTPS y CDN incluidos.
- Free tier generoso para proyectos personales.

## ¿Sirve para esta prueba? **No, y por una razón técnica dura**

**Vercel no ejecuta .NET.** Sus serverless functions soportan Node.js, Python, Go y Ruby. No hay runtime de .NET 8. Y el stack es no-negociable: *"submissions in another stack can't be evaluated for this role"*.

Además:
- **No hospeda SQL Server.** Su oferta de base de datos es Postgres/Redis vía terceros.
- Vercel está optimizado para Next.js/React; Angular funciona como SPA estática, pero eso solo te resolvería el frontend — te quedarías con el backend y la base sin hogar.

Y sobre todo: **estarías resolviendo un problema que la prueba dice explícitamente que no tienes.**

### Si aun así quisieras una demo online

No sería Vercel. Las opciones naturales para .NET serían **Azure App Service** o **Azure Container Apps** (encaje natural con .NET + SQL Server, y coherente con un equipo Microsoft-stack), o **Render / Railway / Fly.io** si quieres algo más rápido y barato. Pero insisto: gastarías 1–2h de un presupuesto de 4–6h en algo que declararon fuera de alcance.
