# CLAUDE.md — Relay / DASH-247

**Before touching aggregation, seeding or the baseline logic, read `PLAN.md` (including the
Amendments and Closing note at the end) and `analysis/README.md`.** The rules below are the
conclusions; those two files carry the measurements they rest on. If a rule looks wrong, the
evidence is there — check it before overriding.

Everything needed to work on this repository is in this file. Nothing here depends on
machine-level configuration, so a fresh clone carries the same rules.

## Language
- Everything written into this repository is in **English**: identifiers, comments, file and
  directory names, documents, test names, commit messages. The language the work is discussed
  in has no bearing on what gets written down.
- The one exception is `ai-log/raw/`. Those are verbatim session transcripts in whatever
  language the session happened in. They are evidence, not prose — never translated.

## Claims and evidence
- Every figure that appears in prose — README, PLAN, comments, commit messages — traces to
  `analysis/` or to a test. Never write a plausible-looking number.
- Any statement about how a tool, engine or library behaves is labelled either **verified**,
  naming what was tested and the scope of the result, or **assumed**. Never ambiguous. The
  decision is how to label, not whether to check; an unlabelled claim is the defect. Worked
  examples: `AT TIME ZONE` rejecting IANA ids is verified against SQL Server 2022 CU26 on
  Ubuntu 22.04 and says so, while the README's toolchain prerequisites are labelled untested.

## Artifacts that are not yours to rewrite
- `seed.sql` is production data. Never edit it. Idempotency comes from wrapping the load, not
  from rewriting the file.
- `PLAN.md`'s body is never edited. A change of mind is appended as a timestamped amendment.
  The value of that file is that it was written before the code; editing it in place destroys
  the only evidence of that.
- `ai-log/raw/` is generated by `ai-log/export-ai-log.ps1`. Regenerate it. Never hand-edit it,
  never tidy it, never remove a session because it reads badly.

## Data
- Deduplicate on the full value tuple keeping `MIN(id)`; report the excluded count in the API
  response rather than dropping rows silently. There are 12.
- The 2026-06-03 burst (805 events, account 6) **stays in the data**. It is real activity and
  the median absorbs it. Never filter it out as dirty data.
- `location` is unique only *within* an account — `'Site A'` exists in 19 accounts. Every
  query, join, group and filter is scoped by `account_id`.

## Aggregation
- SQL aggregates as far as weekly totals per `(account_id, location, week_start)` and stops.
  Median, MAD, band and status are computed in C#. See PLAN Amendment 2.
- Missing weeks and days materialise as `0`. `GROUP BY` returns only rows that exist; a
  baseline averaged over 5 of 8 weeks is wrong and looks fine.
- Baseline median of 0 → no percentage at all. Never emit `Infinity`, `NaN` or `-100%`.
  `low_volume` (median < 5/week) shows counts and band but suppresses the status badge.

## Time
- Weeks are Monday–Sunday in the **account's local time**, bucketed on `occurred_local_date`.
- `occurred_local_date` is precomputed at load time in C# (`TimeZoneInfo`, IANA-aware) and
  indexed — it keeps the day bucket sargable and the conversion unit-testable without a
  database. Do not move the conversion into the query: `AT TIME ZONE` on this engine rejects
  IANA ids and takes Windows ones, verified in PLAN Amendment 3.
- "Now" is `MAX(occurred_at)`, never `GETUTCDATE()` or `DateTime.Now`. The data ends
  2026-07-27; the system clock renders an empty dashboard.

## Tests
- Golden numbers come from `analysis/`, never from intuition. Needing a new expected value
  means measuring it there first.
- `insufficient_history` and `baseline_zero` have no real data behind them in this seed
  (minimum baseline median is 3.5, minimum history 24 weeks). Test them with synthetic
  fixtures — do not invent seed rows to reach them.

## Stack
- EF Core is the only data-access stack — no Dapper. The pulse aggregate runs through
  `SqlQueryRaw<T>` onto a flat DTO, never an entity, and never as LINQ. (PLAN Amendment 4)
- The aggregation SQL lives in its own `.sql` file embedded as a resource, never as a C#
  string literal, so it can be run straight against the database to check the numbers.
- All UI state — account, week, baseline window, event type — lives in URL query params. Not
  a service field, not `localStorage`. It must survive reload and be shareable by link.
- The frontend calls `/api` relative, proxied to `localhost:5080` by
  `frontend/proxy.conf.json`. Never an absolute URL.
- Mark a `<select>`'s choice with `[selected]` on the `<option>`, never `[value]` on the
  select: the options come from `@for`, so the binding is applied before they exist and is
  then silently lost, leaving every control showing its first entry.
- Look at the running app before calling a UI change done. The suite asserts component state
  and outbound requests, so a page that computes correctly and renders wrongly passes it —
  that is exactly how the `[value]` bug above survived ten green tests.

## Running it
- Stop the API before `dotnet test`. `dotnet run` holds `Relay.Api.exe` open and the test
  build then fails with `MSB3027`, which reads as a compilation error and is not one.

## Commits
- The message says **why**, not what — the diff already says what. Where a change came from
  catching a mistake, the message records the mistake. The history is read here as an
  artifact, not only as a log.

## Out of scope
- Auth, alerting/notifications, ML/forecasting, trend charts, per-event drill-down. Do not add
  them, and do not scaffold them "for later".
